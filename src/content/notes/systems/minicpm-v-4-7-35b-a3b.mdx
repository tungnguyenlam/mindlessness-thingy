MiniCPM-V 4.7 (`openbmb/MiniCPM-V-4.7-35B-A3B`) is the flagship checkpoint of OpenBMB's MiniCPM-V 4.7 multimodal series, pairing a 553M-parameter vision encoder with a 34.7B-parameter (`Qwen3.5-35B-A3B`) hybrid [[gated-deltanet]] and [[moe]] language backbone that activates 3.45B language parameters per token <Cite id="minicpm-v-4-7-35b-a3b-card" where="Overview; model.safetensors.index.json" />. Its sister model (`openbmb/MiniCPM-V-4.7-1B`) shares the identical vision encoder and two-stage compression pipeline on top of a dense 28-layer `Qwen3-0.6B` language model <Cite id="minicpm-v-4-7-1b-config" where="vision_config; text_config" />.

## Whole model

## Two-stage visual token compression

Standard vision-language models run every Vision Transformer layer over the full patch grid before a [[vision-language-connector]] downsamples the tokens at the very end. Adopted from LLaVA-UHD v4, MiniCPM-V 4.7 moves the first $4\times$ compression inside the 27-layer SigLIP2-derived ViT (`insert_layer_id: 6`, after the 7th layer), cutting ViT compute by $55.8\%$ on the remaining 20 layers <Cite id="llava-uhd-v4-paper" where="README; architecture" /> <Cite id="minicpm-v-4-7-35b-a3b-config" where="vision_config.vit_merger_config" />.

Inside `MiniCPMV4_7ViTWindowAttentionMerger` (`vit_merger`), non-overlapping $2 \times 2$ patch windows run local window self-attention (`window_kernel_size: (2, 2)`), concatenate four $1152$-dim vectors into $4608$ dimensions, and pass through $\text{LayerNorm}(4608) \to \text{Linear}(4608 \to 17216) \to \text{GELU} \to \text{Linear}(17216 \to 1152)$ plus a four-patch mean residual <Cite id="minicpm-v-4-7-modeling" where="MiniCPMV4_7ViTWindowAttentionMerger.forward" />. After the final ViT layer, `MiniCPMV4_7Merger` (`model.merger`) groups another $2 \times 2$ window ($4608$) through $\text{LayerNorm}(4608) \to \text{Linear}(4608 \to 4608) \to \text{GELU} \to \text{Linear}(4608 \to 2048)$ into width $d = 2048$ <Cite id="minicpm-v-4-7-modeling" where="MiniCPMV4_7Merger.forward" />.

When `downsample_mode="4x"` is selected for dense OCR or tiny visual details, `get_image_features` sets `use_vit_merger = False`, skipping `vit_merger` so all 27 ViT layers process the unmerged patch grid and only the post-ViT `merger` ($4\times$) runs <Cite id="minicpm-v-4-7-modeling" where="MiniCPMV4_7Model.get_image_features" />. At the default $16\times$ compression, a $1960 \times 1960$ image ($140 \times 140 = 19,600$ patches of $14 \times 14$ pixels) becomes $35 \times 35 = 1,225$ visual tokens (`max_VisTokens: 1225`) <Cite id="minicpm-v-4-7-35b-a3b-card" where="Overview; preprocessor_config.json" />.

## Canvas M-RoPE for sliced images and video

When an ultra-high-resolution image is split into a global thumbnail plus local spatial sub-slices, standard 3D multimodal [[rope]] resets spatial $(h, w)$ coordinates inside each slice, losing where a slice sits on the original image. MiniCPM-V 4.7 introduces `mrope_mode: "canvas"`, which computes each slice token's $(t, h, w)$ position on a unified normalized canvas of the whole image (`canvas_norm_size: 100`) <Cite id="minicpm-v-4-7-35b-a3b-config" where="mrope_mode, canvas_norm_size" /> <Cite id="minicpm-v-4-7-modeling" where="MiniCPMV4_7Model.get_rope_index" />.

Only the first $25\%$ of each $256$-dim query or key head ($64$ dims, or $32$ frequency pairs) is rotated (`partial_rotary_factor: 0.25`, $\theta = 10,000,000$), while $192$ dims pass through unrotated <Cite id="minicpm-v-4-7-35b-a3b-config" where="text_config.rope_parameters" />. Across those $32$ pairs, temporal, height, and width frequencies (`mrope_section: [11, 11, 10]`) are interleaved (`mrope_interleaved: true`) <Cite id="minicpm-v-4-7-35b-a3b-config" where="text_config.rope_parameters" />. For a slice at grid index $(r, c)$ in an $(R, C)$ grid of $(H_s, W_s)$ tokens, token $(i, j)$ receives canvas height $\lfloor r \cdot \frac{100}{R} + i \cdot \frac{100}{R \cdot H_s} \rfloor$ and width $\lfloor c \cdot \frac{100}{C} + j \cdot \frac{100}{C \cdot W_s} \rfloor$ <Cite id="minicpm-v-4-7-modeling" where="MiniCPMV4_7Model.get_rope_index" />.

## Hybrid Gated DeltaNet and gated GQA backbone

By delegating 30 of its 40 layers to [[gated-deltanet]] (`Qwen3_5MoeGatedDeltaNet`) and keeping [[gqa]] (`Qwen3_5MoeAttention`) in only 10 layers (`3, 7, 11, ..., 39`), the backbone bounds its recurrent state while retaining exact long-range retrieval every fourth layer <Cite id="minicpm-v-4-7-35b-a3b-config" where="text_config.layer_types" />.

In each Gated DeltaNet layer, $h_t \in \mathbb{R}^{2048}$ projects to $n_{qk} = 16$ query and key heads of width $d_{qk} = 128$ ($2048$ each, L2-normalized and repeated $2\times$ to match $32$ value heads) and $n_v = 32$ value heads of width $d_v = 128$ ($4096$), passes through a causal depthwise $\text{Conv1d}$ of kernel $k = 4$ over all $8192$ channels, and updates the FP32 matrix state $S_t \in \mathbb{R}^{32 \times 128 \times 128}$ via $S_t = \alpha_t S_{t-1} + \beta_t (v_t - S_{t-1} k_t) k_t^\top$ before gated normalization $\text{RMSNorm}(S_t q_t) \odot \text{SiLU}(z_t)$ <Cite id="qwen3-5-moe-modeling" where="Qwen3_5MoeGatedDeltaNet.forward" />.

In the 10 full-attention layers, `head_dim` is $256$—twice $d / n_h = 128$—so $16$ query heads span $4096$ dimensions while $2$ [[kv-cache]] heads span $512$ dimensions ($8:1$ GQA) <Cite id="minicpm-v-4-7-35b-a3b-config" where="text_config.head_dim, num_attention_heads, num_key_value_heads" />. With `attn_output_gate: true`, `q_proj` outputs $8192$ dimensions ($2 \times 4096$), splitting off a query-conditioned gate $g_Q$ that scales the attention output via $\sigma(g_Q) \odot \text{Attn}(Q, K, V)$ before `o_proj` ($4096 \to 2048$) <Cite id="qwen3-5-moe-modeling" where="Qwen3_5MoeAttention.forward" />. Every layer's [[moe]] block routes tokens to the top $8$ of $256$ SwiGLU experts ($d_e = 512$) via softmax and adds one shared expert (`shared_expert_intermediate_size: 512`) gated by $\sigma(w_{\text{shared}}^\top u_t)$ <Cite id="qwen3-5-moe-modeling" where="Qwen3_5MoeSparseMoeBlock.forward" />.

<Callout type="pitfall">
Although `text_config` contains `"mtp_num_hidden_layers": 1`, the main BF16 checkpoint ships zero `mtp.*` tensors in `model.safetensors.index.json`, and `MiniCPMV4_7PreTrainedModel` explicitly sets `_keys_to_ignore_on_load_unexpected = [r"^mtp.*"]` <Cite id="minicpm-v-4-7-modeling" where="MiniCPMV4_7PreTrainedModel" />. Speculative decoding instead uses the separate 5-layer DSpark checkpoint (`openbmb/MiniCPM-V-4.7-35B-A3B-DSpark`) <Cite id="minicpm-v-4-7-35b-a3b-dspark-card" where="README" />.

## Inference: LES, layer-wise quantization, and DSpark

Because $93.4\%$ of the language backbone's parameters ($32.36\text{B}$ of $34.66\text{B}$) live in the 256 routed experts per layer while only 8 experts ($3.125\%$) run per token, OpenBMB pairs the model with three inference optimizations across `llama.cpp-omni`, SGLang, and vLLM <Cite id="minicpm-v-4-7-35b-a3b-card" where="Inference; Deployment" />.

- **Lookahead Expert Scheduling (`LES`)**: Because residual updates across adjacent layers are small, `llama.cpp-omni` multiplies the hidden state at layer $l$ by the router matrix of layer $l + N$ ($N \in [1, 8]$) to predict its top-8 experts ahead of time and prefetch their weights into cache before layer $l + N$ executes, improving CPU decode speed by $49.1\%$ (`21.6 → 32.2 tok/s`) and hybrid CPU+GPU decode speed by $76.6\%$ (`14.1 → 24.9 tok/s`) <Cite id="minicpm-v-4-7-les-docs" where="Principle; Benchmark Results" />.
- **Layer-wise sensitivity quantization**: Rather than uniform bit-width across all 40 layers, OpenBMB profiles per-layer quantization error and keeps sensitive layers and shared/router projections at higher precision in the official `GGUF` (`Q4_K_M` at $22.0\text{ GB}$ down to `Q2_K` at $13.3\text{ GB}$) and `AWQ` (`24 GB`) checkpoints <Cite id="minicpm-v-4-7-35b-a3b-card" where="Model Zoo; Quantization" />.
- **DSpark speculative decoding (`MiniCPM-V-4.7-35B-A3B-DSpark`)**: A dedicated 5-layer `Qwen3_5MoeForCausalLM` drafter (`4.40B` parameters, keeping the same 256-expert MoE geometry and $248,144$ vocabulary) drafts tokens for target verification in SGLang (`--speculative-algorithm EAGLE`), reaching up to $2.25\times$ decoding speedup <Cite id="minicpm-v-4-7-35b-a3b-dspark-card" where="config.json; Usage" />.
