LFM2.5-350M is the 350M LFM2 hybrid trained further. The block recipe is still [[hybrid-conv-attention]]: 10 [[gated-short-conv]] layers and 6 [[gqa]] layers, then SwiGLU. What changed from LFM2-350M is the training budget — pretraining extended from 10T to 28T tokens — and a larger post-training stack with reinforcement learning <Cite id="lfm2-5-350m-blog" />. This note is that checkpoint. Follow the architecture links for the mixer.

<Callout type="pitfall">
The LFM2 report lists feed-forward width 4608 for LFM2-350M <Cite id="lfm2-report" where="Table 1" />. The released LFM2.5-350M config has `intermediate_size: 6656`. Use the config for this checkpoint. The same config sets `max_position_embeddings` to 128000; the card's supported context is 32,768.
</Callout>

## What is new

### More pretraining, then RL

LFM2 dense models were pretrained for 10T tokens at 4K context, then 1T of mid-training at 32K <Cite id="lfm2-report" where="§3.2" />. The 350M LFM2.5 blog describes the 2.5 generation as that same architecture with pretraining extended from 10T to 28T, plus large-scale reinforcement learning <Cite id="lfm2-5-350m-blog" />. The card lists the training budget as 28T tokens <Cite id="lfm2-5-350m-card" where="Training budget" />.

The authors highlight three scores that moved relative to LFM2-350M: IFBench 18.20 → 40.69, CaseReportBench 11.67 → 32.45, and BFCLv3 22.95 → 44.11 <Cite id="lfm2-5-350m-blog" />. They still recommend the model for extraction and tool use, not for math, code, or creative writing <Cite id="lfm2-5-350m-card" />.

## What it reuses

- [[gated-short-conv]] for local mixing in 10 of 16 layers, kernel 3.
- [[gqa]] with 16 query heads sharing 8 key/value heads, plus [[rope]] on the attention layers.
- [[kv-cache]] only in those 6 attention layers; convolution layers keep a short window.

[[lfm2-5-230m]] is distilled from this size. [[lfm2-5-1-2b-instruct]] uses the same 16-layer interleaving at hidden size 2048.
