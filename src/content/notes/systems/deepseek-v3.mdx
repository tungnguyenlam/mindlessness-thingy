DeepSeek-V3 is a scaled-up [[deepseek-v2]]. The attention design is the same [[mla]], and the feed-forward layers are still [[deepseek-moe]]. What changed is mostly about training a model this large cheaply and stably: how experts are kept evenly loaded, an extra training objective, and 8-bit arithmetic. This note covers those differences. For anything it reuses, follow the links.

## One layer

Each of the 61 layers is a standard pre-norm [[transformer-block]]: attention, then a feed-forward network, each with a residual connection. In all but the first three layers, the feed-forward network is a mixture of experts <Cite id="deepseek-v3-report" where="§4.2" />.

## What changed from V2

### Balancing experts without a balancing loss

An MoE router left alone tends to send most tokens to a few favourite experts. V2 fought this with three auxiliary losses that penalise imbalance. Those losses also pull the model away from its real objective, so a strong balancing loss costs quality.

V3 replaces them with [[aux-loss-free-balancing]]. Each expert gets a bias that is added to its routing score only when picking the top experts. After each training step, overloaded experts have their bias lowered and underloaded experts raised, by a fixed step $\gamma$. The bias never enters the gating weight itself, so it steers selection without distorting the output <Cite id="deepseek-v3-report" where="§2.1.2" />. A very small sequence-level balance loss remains as a safety net.

Two smaller routing changes come with it. Affinity scores use a sigmoid, normalised over the selected experts, where V2 used a softmax. And each token's experts are limited to at most 4 nodes of the cluster, to cap cross-node communication <Cite id="deepseek-v3-report" where="§2.1.2" />.

$\gamma$ is 0.001 for the first 14.3T training tokens and 0 for the last 500B, so the routing settles at the end of training <Cite id="deepseek-v3-report" where="§4.2" />.

### Predicting one more token

V3 trains with [[mtp]]: alongside the normal next-token prediction, a small extra module predicts the token after that. It shares the embedding and output head with the main model and runs one extra transformer block. The extra loss is weighted 0.3 for the first 10T tokens and 0.1 afterwards <Cite id="deepseek-v3-report" where="§4.2" />.

At inference the module can be dropped. Or it can draft the second token for speculative decoding: DeepSeek reports the draft is accepted 85–90% of the time, for about 1.8× more tokens per second <Cite id="deepseek-v3-report" where="§5.4.3" />.

### Training in FP8

Most large matrix multiplies run in 8-bit floating point, using the E4M3 format throughout. 8-bit numbers have little range, so a single outlier would wreck a tensor-wide scale. V3 scales small pieces separately instead: activations in 1×128 tiles and weights in 128×128 blocks, with partial sums periodically promoted to FP32 <Cite id="deepseek-v3-report" where="§3.3" />. Details belong in [[fp8-training]].

### No token dropping

V2 dropped tokens that overflowed an expert's capacity during training. Because balancing works well enough, V3 drops none, in training or inference <Cite id="deepseek-v3-report" where="§2.1.2" />.

## What came next

[[deepseek-v3-2]] kept this architecture and added [[dsa]], a learned sparse attention. [[deepseek-v4]] then changed the attention and MoE designs much more substantially.
