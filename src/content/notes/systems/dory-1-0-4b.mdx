Dory 1.0-4B is a 4B-parameter [[looped-transformer]] built on a normalized-GPT (nGPT) backbone with interleaved sliding-window attention and full attention <Cite id="dory-1-0-4b-card" where="Model Summary" />. Its two main ideas are **elastic inference depth** (1, 2, or 4 loops from a single checkpoint) and **last-loop KV caching** to keep context memory flat as loops increase <Cite id="dory-1-0-4b-card" where="Highlights" />.

## Elastic loop stack

Dory divides its 36 physical layers into three blocks: an 8-layer Input block ($I$), a 20-layer Recurrent block ($R$), and an 8-layer Output block ($O$) <Cite id="dory-1-0-4b-card" where="Looped LM architecture" />. The input representation is reinjected into $R$ on every pass, and the operator chooses $K \in \{1, 2, 3, 4\}$ at inference time without retraining <Cite id="dory-1-0-4b-card" where="Choosing the Loop Count" />.

NVIDIA recommends 2 loops as the default because most of the accuracy gain arrives on the second pass—for example, SWE-bench Verified rises from 50.3% at 1 loop to 59.5% at 2 loops and 61.8% at 4 loops—while solving tasks in fewer generated output tokens <Cite id="dory-1-0-4b-card" where="Benchmarks, Quick Start Guide" />.

## Last-loop KV caching and specifications

Standard looping stores a separate [[kv-cache]] for every pass, multiplying context VRAM by $K$. Dory supports a `last_loop` mode where each recurrent attention layer overwrites its previous pass's keys and values in place, holding KV memory at the 1-loop size for any loop count with accuracy close to `per_loop` mode <Cite id="dory-1-0-4b-card" where="Reducing the KV Cache Memory Overhead" />.
