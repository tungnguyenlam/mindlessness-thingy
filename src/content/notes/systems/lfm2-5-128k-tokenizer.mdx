[[lfm2-5-2-6b-base]] and [[lfm2-5-2-6b]] read text through a bigger version of the [[lfm2-tokenizer]]. To better support non-Latin scripts, Liquid doubled the vocabulary to 128K by extending the existing tokenizer in place instead of retraining the model from scratch <Cite id="lfm2-5-2-6b-blog" where="Training" />. The pre-tokenizer rules are the same.

## How it splits text

<TokenizerFlow tokenizer="lfm2-5-128k" samples={["vietnamese", "chinese", "japanese", "english", "code"]} />

On Vietnamese, most words are now one token and no letter falls back to byte pieces; the 65K tokenizer spread each of those accented letters over two byte tokens. One more rule changes the lookup itself: a piece that is already a whole token is taken as is, before any merges run <Cite id="lfm2-5-2-6b-tokenizer" where="model.ignore_merges" />.

"In place" holds for the merges: every old rule is still in the list, so the new tokenizer only adds ways to merge. The ids moved, though. No old token kept its id, and the special tokens moved from the start of the table to the end. An LFM2 embedding row therefore doesn't line up with the same id here.

## Ids and embedding rows

The ids run to 125,016 <Cite id="lfm2-5-2-6b-tokenizer" where="added_tokens" /> and the embedding table has 128,000 rows <Cite id="lfm2-5-2-6b-config" where="vocab_size" />. Unlike the 65K files, this tokenizer doesn't add the begin-of-sequence token by itself; the chat template writes it <Cite id="lfm2-5-2-6b-tokenizer" where="post_processor; chat_template.jinja" />. The Base model's file has the same vocabulary and merges, with a slightly different regex for contractions and line breaks <Cite id="lfm2-5-2-6b-base-tokenizer" />.
