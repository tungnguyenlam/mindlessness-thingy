GLM-5.4 is Z.ai's ~750B-parameter coding flagship built on a [[looped-transformer]] architecture <Cite id="glm-5-4-blog" where="Introduction" />. Rather than training a looped model from scratch, Z.ai adapted an already pre-trained GLM-5 base model through continued training, running 28 layers for two passes with **per-token residual gates** and a **hybrid KV cache** <Cite id="glm-5-4-blog" where="From Pre-Trained Base to Loop Transformer" />.

## Gated two-pass refinement and hybrid KV cache

Directly overwriting hidden states across loops causes activation norms to blow up, so GLM-5.4 adds independent per-token gates for each iteration <Cite id="glm-5-4-blog" where="From Pre-Trained Base to Loop Transformer" />. Pass 1 writes conservatively to build global context (more aggressively on harder tokens), and Pass 2 opens the gates to write full refinements.

To avoid doubling [[kv-cache|KV cache]] memory at 1M context lengths, Pass 2 reuses the sparse KV entries and attention indices selected in Pass 1—adding zero indexing overhead—while storing only a small independent sliding window of new Pass-2 KV states <Cite id="glm-5-4-blog" where="Hybrid KV Cache" />.

## Scaling findings and specifications

On controlled 30B iso-parameter ablations, adding the second loop cost ~10% more training compute while cutting average output lengths on GPQA-Diamond and MMLU-Pro by 10–14% as reasoning moved from explicit chain-of-thought tokens into implicit loop depth <Cite id="glm-5-4-blog" where="Scaling Correctness" />.
