StableHand isn't a language model. It reads first-person (egocentric) video and outputs a 3D trajectory for both hands in world coordinates. Per-frame hand estimators fail exactly when the data is most useful: when a hand leaves the view or is hidden behind the object it is holding. StableHand fills those gaps from a learned prior of two-handed motion, so that large collections of human video can supervise robot learning <Cite id="stablehand-repo" where="README, Highlight" />.

The core trick is to decide, per frame and per body part, how far to trust the observation. That decision then shapes the [[flow-matching]] process itself, not just its inputs.

## The pipeline

<ModelOverview model="stablehand" caption="Generated from StableHand's model data, the paper version. The released code differs; see the last section." />

Two frozen off-the-shelf models produce noisy observations. A quality network scores them, and the DiT keeps trusted parts close to the observation while it regenerates the rest. Each hand's state per frame is 54 numbers: a 3D world translation, a 6D wrist rotation, and 45 [[mano]] finger joint angles. Two hands make 108 per frame <Cite id="stablehand-paper" where="§3" />.

WiLoR <Cite id="wilor-paper" /> provides a noisy per-frame estimate of the same 54 numbers in camera coordinates, plus a visual feature. Depth Anything 3 <Cite id="depth-anything-3-paper" /> provides the camera pose that lifts those estimates into the world frame. Both stay frozen <Cite id="stablehand-paper" where="§3, App. A" />.

## Scoring each observation

<Calc
  title="From error to trust score"
  inputs={[

    { id: 'p80', label: '80th-percentile error of the corpus (mm)', min: 5, max: 120, step: 1, value: 60 },
  ]}

    { label: 'Bandwidth σ = p80 / ln 10 (mm)', expr: 'p80 / Math.log(10)', format: 'number', role: 'op' },
    { label: 'Quality q = exp(−e / σ)', expr: 'Math.exp(-e * Math.log(10) / p80)', format: 'percent', role: 'activation' },
  ]}
  note="At the 80th-percentile error the score is exactly 0.1, so the worst fifth of frames scores below that. Set the two sliders equal to see it."
/>

A single trust score per frame would be too coarse. Wrist error is dominated by global translation drift on the scale of tens of millimetres, while finger error lives at the millimetre scale <Cite id="stablehand-paper" where="§3.1" />. So each frame gets four scores, for the wrist and fingers of each hand.

During training, a score comes from the measured error $e$ through $q = \exp(-e/\sigma)$. The bandwidth $\sigma$ is set to the 80th-percentile error divided by $\ln 10$, so the worst 20% of frames score below 0.1. Frames with no detection score 0 <Cite id="stablehand-paper" where="Eqs. 1–3, §3.1" />.

At test time there is no ground truth, so a small transformer, the quality network, predicts the error in millimetres from the world-frame observation, a detection flag and the camera pose. It is deliberately not shown WiLoR's visual features, which let it learn a dataset-specific shortcut. It is trained on about 10M frames from 8 egocentric datasets, with an extra Wasserstein loss that keeps its predictions from collapsing toward the mean <Cite id="stablehand-paper" where="§3.2, Eqs. 5–7" />.

## Quality-aware flow matching

This is what's new. Standard [[flow-matching]] moves every coordinate from noise $\varepsilon$ to data $x_1$ along the same straight line, $x_\tau = \tau x_1 + (1-\tau)\varepsilon$, and trains the network to predict the velocity $x_1 - \varepsilon$. StableHand broadcasts the four scores to all 108 coordinates as $\tilde q$ and gives each coordinate its own schedule <Cite id="stablehand-paper" where="Eq. 8" />:

$$
\alpha(\tau, \tilde q) = 1 - (1-\tau)(1-\tilde q), \qquad x_\tau = \alpha \odot x_1 + (1-\alpha) \odot \varepsilon, \qquad u_\tau = (1-\tilde q) \odot (x_1 - \varepsilon)
$$

With $\tilde q = 0$ this is ordinary flow matching. With $\tilde q = 1$ the coordinate sits at the data from the start and its target velocity is zero. Everything in between starts partly formed and has less distance to travel.

<Calc
  title="One coordinate's schedule"
  inputs={[
    { id: 'q', label: 'Quality q̃', min: 0, max: 1, step: 0.05, value: 0.6 },
    { id: 't', label: 'Flow time τ', min: 0, max: 1, step: 0.05, value: 0 },
  ]}
  outputs={[
    { label: 'Weight on clean motion α', expr: '1 - (1 - t) * (1 - q)', format: 'percent', role: 'activation' },
    { label: 'Weight on noise 1 − α', expr: '(1 - t) * (1 - q)', format: 'percent', role: 'activation' },
    { label: 'Target speed relative to plain flow matching', expr: '1 - q', format: 'percent', role: 'op' },
  ]}
  note="At τ = 0 the weight on clean motion equals q̃. That is why sampling can start from q̃·observation + (1 − q̃)·noise and match training exactly."
/>

Sampling uses the same idea. Instead of starting every coordinate from pure noise, it starts from $x_0 = \tilde q \odot \bar y + (1-\tilde q) \odot \varepsilon$, a per-coordinate mix of the observation and noise. That matches the training distribution at $\tau = 0$ because $\alpha(0, \tilde q) = \tilde q$. It then integrates the learned velocity with 20 Euler steps <Cite id="stablehand-paper" where="Eq. 11, §3.3, §4.1" />. The paper contrasts this with SDEdit-style editing, which starts every coordinate from one shared noise level <Cite id="stablehand-paper" where="§3.3" />.

## The denoiser

<ModelDiagram model="stablehand" caption="One of the 8 DiT blocks, generated from the model data. The norms are AdaLN, so the flow time and the quality scores set their scale and shift." />

The [[dit]] gets four tokens per frame (left wrist, left fingers, right wrist, right fingers) and runs temporal self-attention with [[rope]] over all $4T$ tokens. Cross-attention brings in the scene token, camera pose and per-hand observations. The quality scores enter through [[adaln]]: each token's modulation comes from $\text{MLP}_\tau(\tau) + \text{MLP}_q(\tilde q_t)$, so wrist and finger tokens are updated at different strengths <Cite id="stablehand-paper" where="§3.3" />. There is no classifier-free guidance.

On HOT3D <Cite id="hot3d-paper" />, world-space joint error drops to 57.83 mm, from 71.89 mm for HaWoR, the strongest baseline with public code <Cite id="stablehand-paper" where="Tab. 1" />. On ARCTIC <Cite id="arctic-paper" />, it is 124.59 mm against 166.21 mm for HMP-SLAM <Cite id="stablehand-paper" where="Tab. 2" />.

<Callout type="pitfall">
The regenerated frames are plausible motion, not measurements. Over long stretches of low-quality input the model "may drift toward plausible but not faithfully grounded configurations". The quality signal is also calibrated to one upstream estimator <Cite id="stablehand-paper" where="§5" />. Swapping WiLoR for HaMeR means retraining, and even then the HOT3D error rises to 62.16 mm <Cite id="stablehand-paper" where="App. B.3, Tab. 5" />. If you use the output as robot training data, keep the quality scores alongside it.
</Callout>

The fork at `tungnguyenlam/stablehand` has no changes of its own. It is identical to upstream at commit `0471a45e32` <Cite id="stablehand-repo" />. That code is the September 2026 "enhanced version", not the paper model <Cite id="stablehand-enhanced-docs" />:

- VGGT-Omega replaces Depth Anything 3 for camera poses and scene features.
- The wrist is predicted as a residual on top of a smoothed WiLoR trajectory, in a gravity-aligned world frame.
- Each hand's visual feature is projected to a compact vector before conditioning. Joint velocity and acceleration losses replace the wrist-translation loss.
- The quality network also sees local depth around each hand.

The enhanced model reports 45.19 mm on HOT3D and 92.52 mm on ARCTIC <Cite id="stablehand-enhanced-docs" />. The released DiT config keeps 8 layers and 8 heads with 150-frame clips <Cite id="stablehand-dit-hot3d-config" where="layers, heads, max_len" />. Its feed-forward layers are SwiGLU in code, where the paper says GeGLU. Training code has not been released yet <Cite id="stablehand-repo" where="README, TODO List" />.

## Where it sits on the map

StableHand shares the low-level machinery with the language-model notes: the [[transformer-block]], [[rope]] for positions, and attention. It uses it differently: a language model generates one token at a time and keeps a [[kv-cache]], whereas StableHand refines a whole 150-frame clip at once over 20 integration steps, leaving nothing to cache between steps.

Its own branch of the map runs through [[flow-matching]], [[dit]] and [[adaln]] for generation, and [[mano]] for the hands. [[flowhoi]] reuses the same 8-block `AXD` DiT layout to synthesize bimanual hand and 6D object trajectories from a single initial frame, a language prompt, and a 3DGS scene.
