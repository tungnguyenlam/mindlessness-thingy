[[mla]] shrinks what each token stores in the [[kv-cache]], but a query still scores every cached latent, so core attention work grows with the square of the context length <Cite id="deepseek-v3-2-report" where="§2.3" />. DeepSeek Sparse Attention (DSA), introduced in [[deepseek-v3-2]], changes which keys are read instead: a small lightning indexer scores the past cheaply, and full attention runs only on the $k$ best-scoring tokens of it.

Each row is one query token, each cell a key it may read. The indexer gives every past token a score, and only the $k$ highest-scoring keys reach the real attention. In DeepSeek-V3.2 that budget is 2048 key-value tokens per query <Cite id="deepseek-v3-2-config" where="config.json: index_topk" />, the same for every query, whatever the context length.

## How it works

For a query token $t$ and a past token $s$, the indexer produces one score:

$$
I_{t,s} = \sum_{j} w_{t,j}^{I} \cdot \operatorname{ReLU}\!\left(\mathbf{q}^{I}_{t,j} \cdot \mathbf{k}^{I}_{s}\right)
$$

The sum runs over the indexer's heads; each head compares a query-side vector with the past token's key, both projected from the hidden states, and $w_{t,j}^{I}$ is a learned weight per head. There is no softmax and no value mixing — the indexer only ranks. The report says ReLU was chosen for throughput and that the indexer, having few heads, can run in FP8 <Cite id="deepseek-v3-2-report" where="§2.1, eq. 1" />.

Selection then cuts the ranked list down to $k$, and attention reads only the survivors:

$$
\mathbf{u}_t = \operatorname{Attn}\!\left(\mathbf{h}_t,\ \left\{\mathbf{c}_s \mid I_{t,s} \in \operatorname{Top\text{-}k}(I_{t,:})\right\}\right)
$$

Here $\mathbf{c}_s$ is the cached [[mla]] latent of token $s$ <Cite id="deepseek-v3-2-report" where="§2.1, eq. 2" />. MLA runs in its MQA mode inside DSA: all query heads of a query token share one latent, so there is a single key-value entry per past token to score and to select <Cite id="deepseek-v3-2-report" where="§2.1, App. A" />.

The indexer earns its keep by being small: 64 heads of 128 dimensions each compare one query vector against one key vector per past token, with no softmax and no weighted sum of values <Cite id="deepseek-v3-2-config" where="config.json: index_n_heads, index_head_dim" />. Full attention, with its softmax and value mixing over many heads, then runs over at most $k$ latents per query. This suggests the ranking only has to be roughly right: the expensive path never sees the tokens the indexer drops.

## What it costs

The indexer does not remove the scan of the past — it makes it cheap. Scored for every query-token pair, it is still $O(L^2)$ over a sequence, and every attention layer pays an extra scoring pass before it can start reading <Cite id="deepseek-v3-2-report" where="§2.3" />. A selection is also a bet: a token ranked below the cut never enters attention, so the number that matters is how often the tokens full attention would have used survive the cut. The report argues parity through benchmarks rather than a recall figure <Cite id="deepseek-v3-2-report" where="§2.2" />, so treat recall as unverified here.

<Callout type="pitfall">
"Linear in context length" describes the main model's core attention, not the whole layer. The indexer still looks at every past token; what DSA buys is that looking is one small dot product per head instead of a full attention pass.
</Callout>
