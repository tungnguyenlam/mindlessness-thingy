<Words>

A language model generates one token at a time. To produce token $t$, every attention layer needs the keys and values of tokens $1 \dots t-1$. Those don't change once computed, so instead of recomputing them at every step, the model keeps them in memory. That memory is the KV cache.

The cache saves computation but costs memory, and it costs time too. Generating each new token means reading the entire cache from GPU memory once per layer, while doing only a small amount of arithmetic with it. Shazeer observed that this memory traffic, not the arithmetic, dominates incremental decoding time <Cite id="mqa-paper" where="§2" />. Shrinking the cache therefore helps twice: more sequences fit, and each step finishes sooner.

</Words>

## What it costs

Each layer saves one key and one value per key/value head, per token, per sequence:

$$
\text{KV cache} = 2 \times L \times n_{kv} \times d_h \times \text{tokens} \times \text{batch}
$$

<Words>

$L$ is the number of layers, $n_{kv}$ the number of key/value heads and $d_h$ the head dimension. Multiply by bytes per element (2 for FP16/BF16) to get memory. The number of parameters is not in the formula. A model's weights are a fixed cost, but the cache grows linearly with both context length and the number of sequences served at once. At the default settings a single 8K-token sequence already needs a few gigabytes. Serve 32 of them and the cache is bigger than the weights.

</Words>
