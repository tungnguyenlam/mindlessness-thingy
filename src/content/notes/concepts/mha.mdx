Attention lets every token look at every earlier token and pull in a weighted mix of their information. Multi-head attention (MHA) does this several times in parallel with different learned projections, then stitches the results together. It is the baseline that [[mqa]], [[gqa]] and [[mla]] all modify.

## One head

Each token's hidden vector $h_t \in \mathbb{R}^d$ is projected three ways: a query (what am I looking for?), a key (what do I contain?), and a value (what do I hand over if picked?).

$$
q_t = W^Q h_t, \quad k_t = W^K h_t, \quad v_t = W^V h_t
$$

The output for token $t$ is a softmax-weighted sum of values, where the weights come from how well its query matches every key up to and including position $t$:

$$
o_t = \sum_{j \le t} \operatorname{softmax}_j\!\left(\frac{q_t^\top k_j}{\sqrt{d_h}}\right) v_j
$$

Dividing by $\sqrt{d_h}$ keeps the dot products from growing with head size, which would otherwise push the softmax into a near one-hot regime with tiny gradients <Cite id="attention-is-all-you-need" where="§3.2.1" />.

## Many heads

With $n_h$ heads, each head gets its own $W^Q_i, W^K_i, W^V_i$ that project down to a smaller head dimension $d_h$, usually $d_h = d / n_h$. The heads run independently, their outputs are concatenated back to width $n_h d_h$, and a final projection $W^O$ mixes them.

<Callout type="intuition">
One head might learn to attend to the previous token, another to the subject of the sentence, another to a matching bracket. Splitting the width into heads lets the layer keep several such patterns at once instead of averaging them into one blurry distribution.
</Callout>

## Why later variants exist

The compute in MHA is fine on modern hardware. The problem shows up during generation: every key and value vector for every head, layer and past token has to stay in memory so the next token can attend to it. That store is the [[kv-cache]], and for MHA it grows with $2 \cdot n_h \cdot d_h$ numbers per token per layer.

Every variant on the path from here to [[mla]] is an answer to the same question: how few numbers per token can we keep while attention still works as well?

With DeepSeek-V2's shape, MLA stores what GQA with 2.25 groups would <Cite id="deepseek-v2-report" where="§2.1.4, Table 1" />.

| Variant | What is stored per token per layer | Idea |
| --- | --- | --- |
| MHA | $2 n_h d_h$ | Every head keeps its own key and value |
| [[mqa]] | $2 d_h$ | All heads share one key and one value |
| [[gqa]] | $2 n_g d_h$ | Heads are split into $n_g$ groups that share |
| [[mla]] | $d_c + d_h^R$ | Store one compressed latent and rebuild keys and values from it |

<Callout type="pitfall">
"Heads" means query heads unless stated otherwise. In GQA and MQA there are fewer key/value heads than query heads, and mixing up the two counts is the most common source of wrong KV cache numbers.
</Callout>
