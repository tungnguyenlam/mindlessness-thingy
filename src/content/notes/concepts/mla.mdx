[[gqa]] shrinks the [[kv-cache]] by keeping fewer key/value heads. Multi-head latent attention (MLA), introduced in [[deepseek-v2]], takes a different route: keep all the heads, but don't store their keys and values at all. Store one compressed vector per token and rebuild the keys and values from it on the fly <Cite id="deepseek-v2-report" where="§2.1" />.

## Low-rank joint compression

For each token, a down-projection squeezes the hidden state into a small latent $c^{KV}_t$ of width $d_c$, much smaller than $n_h d_h$. Two up-projections recover per-head keys and values from it:

$$
c^{KV}_t = W^{DKV} h_t, \qquad k^C_t = W^{UK} c^{KV}_t, \qquad v^C_t = W^{UV} c^{KV}_t
$$

Only $c^{KV}_t$ goes into the cache. Keys and values are a deterministic function of it, so nothing is lost by throwing them away.

<Callout type="intuition">
Keys and values for all 128 heads are highly redundant: they are all linear functions of the same hidden state. MLA bets that a few hundred numbers are enough to capture what the heads actually need, and learns the compression end to end instead of fixing it by dropping heads.
</Callout>

## The absorption trick

Rebuilding every past token's keys at every step would cost a lot of compute. It doesn't have to happen. The attention score for head $i$ is

$$
q_{t,i}^\top k^C_{j,i} = q_{t,i}^\top W^{UK}_i c^{KV}_j = \big(W^{UK\top}_i q_{t,i}\big)^\top c^{KV}_j
$$

so $W^{UK}$ can be multiplied into the query side once, and the query is then compared directly against cached latents. The same associativity lets $W^{UV}$ fold into the output projection $W^O$. At inference time, keys and values are never materialised <Cite id="deepseek-v2-report" where="§2.1.2" />.

## Why RoPE needs a side channel

[[rope]] rotates queries and keys by an angle that depends on position. That rotation sits between $q$ and $W^{UK}$, and since it changes with position, it can't be folded into a fixed matrix. Applying RoPE to the rebuilt keys would break the absorption trick.

MLA's fix is decoupled RoPE: position goes through a separate, small channel. Each head gets an extra query part $q^R_{t,i}$, and all heads share one extra key $k^R_t = \operatorname{RoPE}(W^{KR} h_t)$ of width $d_h^R$. The full key for head $i$ is the concatenation $[k^C_{t,i}; k^R_t]$. The shared RoPE key is cached alongside the latent <Cite id="deepseek-v2-report" where="§2.1.3" />.

<Stepper title="One decoding step with MLA">
  <Step title="Compress the new token">
    The new hidden state $h_t$ is projected down to the latent $c^{KV}_t$ (width $d_c$) and to the shared RoPE key $k^R_t$ (width $d_h^R$), which gets rotated for position $t$.
  </Step>
  <Step title="Append to the cache">
    Both vectors are appended to the cache. That is $d_c + d_h^R$ numbers per layer for this token, regardless of the number of heads.
  </Step>
  <Step title="Build absorbed queries">
    For each head, the query's content part is multiplied by $W^{UK\top}_i$ so it lives in latent space. The RoPE part of the query stays as it is.
  </Step>
  <Step title="Score against the cache">
    Each head scores its absorbed query against every cached latent and its RoPE query against every cached RoPE key, adds the two, scales and applies softmax.
  </Step>
  <Step title="Read out">
    The softmax weights mix the cached latents. The result goes through $W^{UV}$ folded into $W^O$ to produce the layer output.
  </Step>
</Stepper>

## How much it saves

Per token per layer, MLA caches $d_c + d_h^R$ elements. In DeepSeek-V2, $d_c = 4 d_h$ and $d_h^R = d_h / 2$, so the cache equals that of [[gqa]] with only 2.25 groups, while the paper reports quality on par with or better than full [[mha]] <Cite id="deepseek-v2-report" where="§2.1.4, Table 1" />.

<Callout type="pitfall">
Queries are compressed too (the query latent above), but that is for saving activation memory during training. It has nothing to do with the KV cache, which only depends on $d_c$ and $d_h^R$.
</Callout>
