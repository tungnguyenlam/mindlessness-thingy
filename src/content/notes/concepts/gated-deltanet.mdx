Attention keeps every past key and value in a [[kv-cache]] that grows with the text. [[mamba-2]] keeps one fixed-size state instead, but its only way to forget is to shrink every stored memory by the same factor. Gated DeltaNet keeps that fixed state and adds a second tool: it can edit what one key stores without touching the rest. In the authors' words, "gating enables rapid memory erasure while the delta rule facilitates targeted updates" <Cite id="gated-deltanet-paper" where="Abstract" />.

## The idea in one picture

<Scene
  name="gated-delta-update"
  title="Writing, overwriting and forgetting in one fixed matrix"
  caption="Watch the readout on the right when key A gets a new value. Adding blends old and new; the delta rule replaces the old value; the gate fades everything at once."
/>

The state is a matrix $S$ with one column per key dimension and one row per value dimension. A token stores its value $v$ under its key $k$ by adding the outer product $v k^\top$. A later query $q$ reads $o = S q$. When $q$ points the same way as a stored key, it gets back that key's value.

The trouble starts when a key comes back with a new value. Adding again leaves both values in $S$, so the readout is a blend. The delta rule first reads what $S$ already stores under $k$, then writes only the difference. The gate $\alpha$ is the other tool: it scales the whole matrix down, which forgets every memory at once.

## The update rule

  note="Sₜ is the state after token t, αₜ ∈ (0, 1) the gate, βₜ ∈ (0, 1) the write strength. Each layer reads its output as oₜ = Sₜ qₜ."

The delta rule is easier to see when it is split into a read and a write. First read the value currently stored under the key, $S_{t-1} k_t$. Then move the stored value a step $\beta_t$ toward the new value $v_t$:

$$S_t = S_{t-1} + \beta_t \,(v_t - S_{t-1} k_t)\, k_t^\top$$

Multiplying this out gives the DeltaNet row of the table. With $\beta_t = 1$ and a unit-length key, $S_t k_t = v_t$ exactly: the old value is gone and the new one is in its place. Keys at right angles to $k_t$ read the same values as before. The paper reads this as one step of gradient descent on $\tfrac12 \lVert S k_t - v_t \rVert^2$, with $\beta_t$ as the learning rate <Cite id="gated-deltanet-paper" where="§3.1" />.

Gated DeltaNet multiplies the old state by $\alpha_t$ before that step. With $\alpha_t \to 0$ the layer can "promptly clear memory", and with $\alpha_t \to 1$ it edits single keys "without affecting other information" <Cite id="gated-deltanet-paper" where="§1" />. Both $\alpha_t$ and $\beta_t$ are computed from the current token, so the model decides at every step how much to forget and how hard to write.

The layer around the update rule follows the same plan as the paper's block. Here it is as implemented in the Qwen3.5 code, which Qwen3.5, Qwen3.6 and MiniCPM-V 4.7 all use <Cite id="qwen3-5-moe-modeling" where="Qwen3_5MoeGatedDeltaNet" />:

- **A short causal convolution** first. The concatenated q, k and v channels pass through a depthwise convolution of kernel $k$ followed by SiLU, so each one mixes in the few tokens before it. This is the same trick as [[gated-short-conv]], and it is why the layer also keeps a small window of past inputs.
- **Unit-length queries and keys.** q and k are L2-normalised before the update, which keeps the delta rule's read-then-write exact. The query is also divided by $\sqrt{d_{qk}}$.
- **The gate and the write strength.** $\beta_t = \sigma(b_t)$. The gate is $\alpha_t = \exp(-A \cdot \text{softplus}(a_t + \delta))$, where $A > 0$ and the bias $\delta$ are learned per value head. Both $a_t$ and $b_t$ are one number per head, projected from the token.
- **A gated output.** The read $o_t$ is RMS-normalised, multiplied by $\text{SiLU}(z_t)$ from a separate projection of the token, and projected back to width $d$.

<Callout type="pitfall">
The number of value heads $n_v$ can be larger than the number of query/key heads $n_{qk}$. The code repeats each q and k head to serve $n_v / n_{qk}$ value heads: 3 in [[qwen3-6-27b]] (48 / 16) and 4 in [[qwen3-5-397b-a17b]] (64 / 16) <Cite id="qwen3-5-moe-modeling" where="torch_recurrent_gated_delta_rule" />. It is the reverse of [[gqa]], where key/value heads are the ones shared. The state has one matrix per value head, so its size is $n_v \times d_{qk} \times d_v$, not $n_{qk} \times \dots$
</Callout>

Decoding one token costs the same at every position, and the state is a fixed size. In the Qwen models it is kept in FP32 <Cite id="qwen3-6-27b-config" where="text_config.mamba_ssm_dtype" />. With $n_v = 48$ and $d_{qk} = d_v = 128$, as in [[qwen3-6-27b]], that is $48 \cdot 128 \cdot 128$ numbers, or 3 MB per layer, whatever the context length <Cite id="qwen3-6-27b-config" where="text_config.linear_num_value_heads, linear_key_head_dim, linear_value_head_dim" />. The calculators in [[qwen3-6-27b]] and [[qwen3-5-397b-a17b]] set this against their KV caches. For training, the recurrence also has a chunkwise form that runs as matrix products over blocks of tokens <Cite id="gated-deltanet-paper" where="§3.3" />. The Qwen code uses that form for prefill and the token-by-token loop for decoding <Cite id="qwen3-5-moe-modeling" where="Qwen3_5MoeGatedDeltaNet.forward" />.

The price is the same as for [[mamba-2]]: a fixed matrix can only hold so many separate key–value pairs, and nothing can be re-read once it is overwritten. This suggests why every model on this site that uses Gated DeltaNet keeps some full attention layers: three DeltaNet layers to one [[gqa]] layer in the Qwen3.5 family. [[hybrid-ssm-attention]] explains that trade with Mamba-2 layers, and the same reasoning applies here.
