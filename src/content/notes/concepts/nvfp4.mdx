Four bits per weight is half of what [[fp8-training]] uses and a quarter of BF16. NVFP4 stores each element as an E2M1 float — one sign bit, two exponent bits, one mantissa bit — and keeps the values usable with two levels of scaling: an FP8 scale per block of consecutive values, and one FP32 scale per tensor <Cite id="nemotron-3-super-report" where="§2.2, Table 3" />. Nemotron 3 Super is the first Nemotron model pretrained in this format <Cite id="nemotron-3-super-report" where="Abstract, §1" />, and Nemotron 3.5 ships its deployment checkpoints quantized with it <Cite id="nemotron-3-5-report" where="§4.1" />.

A block holds 16 values <Cite id="nemotron-3-super-report" where="§2.2, Table 3" />; the scales let each block use E2M1's small range well instead of relying on one global scale. The Nemotron 3.5 report restates the format as E2M1 elements with per-block scales <Cite id="nemotron-3-5-report" where="§4" />.

## What 4-bit buys

Weights are the biggest single tensor group in a large model, and serving is usually bound by how fast they can be read from memory, so halving their bytes is the cheapest speedup available — this suggests the reported 2.43× throughput over BF16 for the quantized Nemotron 3.5 release <Cite id="nemotron-3-5-report" where="Abstract, §4" />.

The scales cost a little of the saving: one FP8 scale per 16 values adds half a bit per element (derived: eight bits over sixteen values), which is why the report measures its NVFP4 KV cache at 4.5 bits per element rather than 4 <Cite id="nemotron-3-5-report" where="§4.5" />.

Across the whole mixed release checkpoint — experts in NVFP4, attention in FP8, embeddings in BF16 — the average lands at 4.82 bits per parameter <Cite id="nemotron-3-5-report" where="§4.1, Table 12" />.

## What it costs

4-bit floats have a narrow range; values outside it are rounded or clipped, so every quantized tensor carries error. Nemotron 3.5 recovers a median 99.62% of the BF16 accuracy across 36 benchmarks <Cite id="nemotron-3-5-report" where="Abstract, §4.1" /> — recovery, not equality — and the most sensitive parts never go to 4 bits <Cite id="nemotron-3-super-report" where="§2.2, Table 3" />.

<Callout type="pitfall">
4-bit weights are not a 4-bit model. Activations run at 4 bits only on Blackwell (W4A4); everywhere else the weights are NVFP4 but the activations stay at 16 bits (W4A16) <Cite id="nemotron-3-5-report" where="§4.1" />.
</Callout>
