[[mqa]] cuts the [[kv-cache]] as far as it can go by giving all query heads a single shared key and value. That works, but quality can drop and training can become less stable. Grouped-query attention (GQA) picks a point in between: split the $n_h$ query heads into $n_g$ groups, and give each group its own key and value head <Cite id="gqa-paper" where="§2.2" />.

- $n_g = n_h$: every head has its own key and value. This is [[mha]].
- $n_g = 1$: one shared key and value. This is [[mqa]].
- Anything in between trades cache size against quality.

The cache per token per layer becomes $2 \cdot n_g \cdot d_h$, a factor of $n_h / n_g$ smaller than MHA.

## Converting an existing model

The GQA paper also shows that an MHA checkpoint can be converted rather than retrained. Key and value heads within a group are mean-pooled into one head, then the model is trained a little longer so it adapts. The authors report that about 5% of the original pre-training compute is enough to recover most of the quality <Cite id="gqa-paper" where="§2.1" />.

<Callout type="pitfall">
GQA does not reduce compute much. Each query head still attends over the full context. What it reduces is memory and the bandwidth spent reading the cache, which is what limits decoding speed.
</Callout>

## Where it stops helping

GQA can only shrink the cache by dropping heads. To go further without collapsing to a single shared head, you need to change what is stored, not just how much of it. That is the step [[mla]] takes.
