Every attention layer adds to the [[kv-cache]] for every token of context. A [[mamba-2]] layer works differently. It folds the past into a recurrent state whose size doesn't depend on sequence length, while attention "requires a cache of size linear in sequence length" <Cite id="mamba2-paper" where="§1" />. A hybrid stack uses mostly the cheap kind and keeps a few of the expensive kind.

## The layout

NVIDIA's Nemotron-H models replace "the majority of self-attention layers" with Mamba layers that need constant compute and memory per generated token <Cite id="nemotron-h-paper" where="Abstract" />. Nemotron 3 keeps the idea and alternates it with [[moe]] layers. Each layer in the stack is exactly one block: a Mamba-2 mixer, an MoE feed-forward, or attention.

Nemotron 3 Super has 88 layers: 40 Mamba-2, 40 MoE and 8 attention <Cite id="nemotron-3-super-config" where="hybrid_override_pattern" />. The pattern, with M for Mamba-2, E for MoE and \* for attention:

```
MEMEMEM*EMEMEMEM*EMEMEMEM*EMEMEMEMEM*EMEMEMEMEM*EMEMEMEMEM*EMEMEMEMEM*EMEMEMEM*EMEMEMEME
```

The report describes the few attention layers as global "anchors" that enable full-token interaction and long-range information routing <Cite id="nemotron-3-super-report" where="§2.1.3" />. Those attention layers also use [[gqa]] with only 2 key/value heads, so even the part of the cache that does grow is narrow.

The SSM line never moves with context length, but it isn't small. One Mamba-2 layer's state here is $128 \times 64 \times 128$ values, 4 MiB in FP32. One attention layer's KV for one token is $2 \times 2 \times 128$ values, 1 KiB in BF16. So a single Mamba-2 layer costs about as much as 4K tokens of one attention layer's cache. That matches the Nemotron 3.5 report's remark that one Mamba cache page is at least about 4K tokens of attention KV <Cite id="nemotron-3-5-report" where="§5.3" />. For short requests a hybrid saves little. The savings appear as context grows into the hundreds of thousands of tokens.

<Callout type="pitfall">
The recurrent state is overwritten at every step, so rounding errors accumulate in a way KV entries don't. Storing Nemotron 3 Super's SSM cache in plain FP16 made outputs up to 37–40% longer. Its released recipe uses FP16 with stochastic rounding instead <Cite id="nemotron-3-super-report" where="§4.3, Table 9" />.
</Callout>

## How it compares

[[mla]] keeps attention in every layer and shrinks what each token stores. [[dsa]] keeps the full cache but reads only part of it at each step. A hybrid removes most of the attention layers and accepts a fixed-size summary for the rest. These are different answers to the same [[kv-cache]] problem, and they can be combined.

Models built this way include [[nemotron-3-nano]], [[nemotron-3-super]] and [[nemotron-3-5-super-vl]].
